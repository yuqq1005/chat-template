## 1. 记忆机制总览

主应用存在 **两套并行记忆**，由 **主模型（聊天）+ 副模型（记忆整理）** 协作：

```
用户发言
   │
   ▼
callAPI(contact)
   ├─ ① 检索 memoryFacts（相关结构化长期记忆）
   ├─ ② buildChatPrompt（静态人设 / 自定义指令 / 能力）
   ├─ ③ buildMessageHistory（历史 + 运行时上下文）
   ├─ ④ 关键词扫描触发 worldBook
   ├─ ⑤ 注入：相关 facts + 世界书 + 时间/音乐/思考模式标记
   ├─ ⑥ 主模型 → 聊天气泡
   └─ ⑦ 副模型 → <memory_ops> + <memory_diff>
         ├─ 写入 memoryEpisodes / memoryFacts（IndexedDB）
         └─ 打补丁更新 contact.memoryTableContent（Markdown）
```

IndexedDB 库名：`WhaleLLTDB`（v14），新增 store：

- `memoryEpisodes`：本轮记忆更新事件
- `memoryFacts`：SPO 结构化事实（可软删除）

联系人本身仍挂在 store `contacts` 上，含 `memoryTableContent`、`worldBook`、`messages` 等字段。

## 2. 记忆机制详解

### 2.1 Markdown「记忆表格」（中短期 / 可读表）

**作用：** 给人看、给副模型做表格增量更新；UI 记忆面板可编辑。

**初始化：** 新建私聊 / 群聊时写入 `defaultMemoryTable`（`memoryTable.js` / `promptBuilder.js`）。

**更新流程：**

1. 主模型只负责聊天。
2. 副模型收到 `buildMemoryUpdatePrompt` + 本轮对话 + `<current_memory>`。
3. 解析 `<memory_diff>[...]</memory_diff>`。
4. `MemoryPatcher` / `MemoryTableManager` 按 op 打补丁，写回 `contact.memoryTableContent`。

**Diff 操作：**

```json
{"op":"update","section":"现在","key":"地点","value":"..."}
{"op":"append","section":"过去","line":"| ... |"}
{"op":"delete","section":"未来","keyword":"..."}
```

**注入策略：** 主聊天默认 **不** 把整张 Markdown 表塞进主提示（`includeFullMemoryTableInMainPrompt: false`）。全表仍用于副模型、微博、待办提醒、主动关怀等场景。

### 2.2 结构化长期记忆（memoryFacts）

**写入优先序：**

1. 副模型输出 `<memory_ops>` → `parseMemoryOps` → `applyMemoryOps`（+ episode）。
2. 若无 ops，则兜底：把 `memory_diff` 转成 facts（`convertMemoryDiffToFacts`）。
3. `memory_diff` 对「未来」的 delete 可失效 future/promise 类 facts。

**检索：**

- 入口：`retrieveRelevantMemoryFacts(contactId, queryText, { limit, minScore })`
- 查询文本：`buildMemoryRetrievalQuery` = 最新用户输入 + 最近 4 条消息
- 评分：`scoreMemoryFact` → 过滤 `minScore`（聊天常用 `limit:10, minScore:7`）→ 相似度去重 → Top N

**注入：**

- `buildRelevantMemoryFactsBlock(facts)` 生成：

```text
--- [相关结构化长期记忆] ---
以下是从长期记忆库中检索到的、与当前对话最相关的事实。...
<relevant_memory_facts>
1. ...
   - 类型: ...
   - 时间范围: ...
</relevant_memory_facts>
```

插入到 `[System Context / 系统实时状态]` 一带，尽量放在最新用户消息之前。

### 2.3 独立页 `线下.html` 的第三种记忆（非主聊天）

基于关键词标签的对话摘要（IndexedDB `summaries`），`findAndInjectRelevantSummaries` 最多注入 3 条匹配摘要到系统提示的 `[ACTIVATED MEMORIES ...]`。与主 App 联系人记忆 **不共用**。

## 3. 记忆数据结构

### 3.1 Contact（主应用角色容器）

```js
{
  id: string,
  name: string,
  avatar: string,
  personality: string,           // 自由文本人设
  customPrompts: string,         // 自定义行为指令（可为 JSON 字符串）
  voiceId: string,
  thinkMode: 'default' | 'inner_os' | 'no_inner_os',
  bubbleStyleId: string,
  type: 'private' | 'group',
  members?: string[],            // 群聊成员 contactId
  isPinned: boolean,
  messages: Message[],
  lastMessage: string,
  lastTime: ISO string,
  memoryTableContent: string,    // Markdown 记忆表
  worldBook: WorldBookEntry[]
}
```

### 3.2 Message

```js
{
  role: 'user' | 'assistant',
  content: string,
  type: 'text' | 'emoji' | 'red_packet' | ...,
  time: ISO / Date,
  senderId: string,
  reasoning?: string
}
```

### 3.3 WorldBookEntry（主应用）

```js
{
  keywords: string,  // 中文逗号「，」分隔
  entry: string      // 触发后注入的设定文本
}
```

### 3.4 memoryEpisode

```js
{
  id: string,                 // episode_${ts}_${rand}
  contactId: string,
  type: 'memory_update',
  content: string,            // 扁平化对话文本
  source: 'secondary_model_memory_ops' | 'secondary_model_memory_diff',
  createdAt: number,
  messageIds: [],
  metadata: {
    memoryOps?: object,
    rawDiff?: array,
    oldMemoryLength?: number,
    newMemoryLength?: number
  }
}
```

### 3.5 memoryFact

```js
{
  id: string,
  contactId: string,
  subject: string,
  predicate: string,
  object: string,
  factText: string,
  sourceEpisodeId: string,
  confidence: number,          // 0–1
  importance: number,          // 0–1
  status: 'active' | 'inactive',
  createdAt: number,
  updatedAt: number,
  validFrom: number,
  validTo: number | null,
  metadata: {
    type?: 'profile' | 'current_state' | 'past_event' | 'future_plan'
         | 'relationship' | 'item' | 'preference' | 'emotional_core' | 'other',
    timeScope?: 'current' | 'long_term' | 'past' | 'future' | 'temporary',
    entities?: Array<{ name, type, aliases, description }>,
    source?: 'memory_ops',
    invalidationReason?: string,
    invalidationSource?: string
  },
  _retrievalScore?: number     // 仅检索运行时
}
```

### 3.6 副模型输出：memory_ops

```js
{
  entities: [{
    name, type, aliases, description
    // type: person|place|item|event|concept|relationship|preference|promise|other

  facts_to_add: [{
    subject, predicate, object, factText,
    type, timeScope, confidence, importance
  }],
  facts_to_invalidate: [{
    subject, predicate, reason

}
```

## 4. 世界书设计

### 4.1 主聊天世界书（自定义简化版）

| 项目 | 行为 |
|------|------|
| 存储位置 | `contact.worldBook[]` |
| 字段 | 仅 `{ keywords, entry }` |
| 关键词分割 | 仅中文逗号 `，` |
| 激活方式 | 近期消息拼接串的 **子串包含** 匹配 |
| 注入格式 | `[补充世界书设定]:\n- entry\n...` |
| 注入位置 | 拼进 System Context，或单独 `[WorldBook / 世界书触发设定]` 用户消息 |
| 缺失能力 | 无 order / scanDepth / position / disable / 大小写 / 整词匹配 |

核心函数：`getTriggeredWorldBookEntries(contact, messageHistory)`（`script.js`）。

**结论：** 主聊天世界书 **不是** SillyTavern lorebook 兼容格式。

### 4.2 工具链中的 ST 风格世界书

`www/支持手机端的地图生成器.html` 可导出类似：

```js
{
  keys: ["地点名"],
  content: "...",
  order: 100,
  position: "before_char",
  disable: false,
  scanDepth: null,
  caseSensitive: false,
  matchWholeWords: false,
  useGroupScoring: true,
  role: 0,
  vectorized: false
}
```

供 SillyTavern 使用；主 Whale 聊天 **不会** 自动把该结构导入 `contact.worldBook`。

## 5. 角色卡设计

### 5.1 主应用：自定义 Contact（非 Tavern 卡）

人设 = 自由文本字段拼接，核心字段：

| 字段 | 用途 |
|------|------|
| `name` | 角色名，写入系统提示「你是 XXX」 |
| `personality` | 主人人设描述 |
| `customPrompts` | 自定义行为指令块 |
| `thinkMode` | 内心 OS / 分析模式标记 |
| `voiceId` | TTS |
| `memoryTableContent` | Markdown 记忆 |
| `worldBook` | 世界书条目 |
| `type` + `members` | 私聊 / 群聊 |

转换器（`转化器*.html`）会把外部数据的 `aiPersona`、`speakingStyle`、`commonExpressions`、`background`、`myPersona` 等拼进 `personality`。

**没有** 主链路的 `spec` / `first_mes` / `character_book` / `mes_example`。

### 5.2 独立页：SillyTavern `chara_card_v2`

`www/线下.html`（标题含 SillyTavern 全功能编辑器）：

- 导入要求：`spec === 'chara_card_v2'` 且存在 `data.name`
- 导出结构：

```js
{
  spec: "chara_card_v2",
  spec_version: "2.0",
  data: {
    name, description, personality, scenario, first_mes, mes_example
  }
}
```

与主 App IndexedDB `contacts` **分离**，不走 `callAPI` 主路径。

### 5.3 预设文件

| 文件 | 形态 |
|------|------|
| `whale预设.json` | `{ title, content }[]` 小说写作向提示块 |
| `whale预设1.2.json` | ST 风格 `{ prompts, prompt_order }` |

主聊天更常用 `customPrompts`；预设更多服务线下编辑器 / 写作流。

#### `buildChatPrompt` 骨架（可直接抽）

```text
你正在进行一次角色扮演。你的所有行为和回复都必须严格遵循以下为你设定的指令。...

--- [绝对核心指令：输出格式] ---
你的唯一任务是扮演角色并生成特定格式的聊天文本。聊天内容中，**每一个气泡（每一句话）占一行**。...
+ 输出格式 / 本回合优先 / 多气泡规则

--- [核心身份与记忆] ---
你是{name}，你的人设是：{personality}。
用户的名字是{userName}。{用户人设}
你必须根据你的人设、记忆、用户的人设和当前对话内容来回复。

--- [群聊场景指令] ---   // 仅 group
...

--- [自定义行为指令] ---
{customPrompts}

--- [你的特殊能力与使用规则] ---
红包 / 表情 / 语音规则
```

#### `INNER_OS_MARKER` / `NO_INNER_OS_MARKER`

```text
【角色沉浸要求】在你的思考过程（<think>标签内）中……
1. 角色第一人称内心独白，用括号包裹……
2. 用第一人称描写内心感受……
3. 思考内容应沉浸在角色中……

【思维模式要求】在你的思考过程（<think>标签内）中……
1. 禁止圆括号内心独白……
2. 禁止角色第一人称内心活动……
3. 聚焦剧情分析与回复规划……
```

#### `buildMemoryUpdatePrompt`（副模型，核心可提取）

```text
你是一个后台记忆整理引擎。
你的任务是冷酷、客观地分析用户与角色的最新对话，提取对长期对话有用的结构化事实……

【优先输出】必须首先输出 <memory_ops>…</memory_ops>，内部为 JSON：
  entities / facts_to_add / facts_to_invalidate

记录原则：
- 只记长期有用事实；不记寒暄
- 偏好、关系、约定、物品、地点、身份、情绪核心优先
- 新事实替代旧事实时必须 invalidate

【兼容旧版】再输出 <memory_diff>…</memory_diff>
  update / append / delete
输出顺序：先 memory_ops，再 memory_diff
```

副模型用户消息模板（`script.js` callAPI 内）：

```text
请分析以下对话记录并提取情报。

{conversationText}

【输出要求】
1. 优先输出完整的 <memory_ops> … </memory_ops>
2. 再输出 <memory_diff> … </memory_diff>；无变更则 <memory_diff>[]</memory_diff>

【当前记忆状态】：
<current_memory>
{currentMemoryMarkdown}
</current_memory>
```

## 9. 迁移到其他项目（如 react-chat）时可复用清单

1. **数据结构：** `memoryFact` / `memoryEpisode` / Markdown 表模板 / `worldBook` 简化条目  
2. **流程：** 主模型聊天 ↔ 副模型记忆整理（双模型）  
3. **提示词：** `buildChatPrompt` 骨架、`buildMemoryUpdatePrompt`、相关 facts 注入块、世界书注入格式、INNER_OS 标记  
4. **检索：** query = 最新用户句 + 最近 N 条；评分 + TopK + 去重  
5. **不必强行兼容 ST：** 若目标是「手机拟真聊天」，保持 Contact 扁平字段即可；需要酒馆互通时再做字段映射层

### SillyTavern V2 → Whale Contact 粗映射（可选）

| ST V2 `data.*` | Whale Contact |
|----------------|---------------|
| `name` | `name` |
| `description` + `personality` | `personality` |
| `scenario` | 拼进 `personality` 或 `customPrompts` |
| `first_mes` | 首条 `messages` assistant（需自行落库） |
| `mes_example` | `customPrompts` 示例段 |
| `character_book.entries` | 转成 `worldBook[{keywords: keys.join('，'), entry: content}]` |
